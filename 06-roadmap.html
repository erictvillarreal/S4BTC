6  Roadmap — Open Gaps

Organized by priority per the most recent research session (CLAUDE_README_RESEARCH_SESSION_MAY25.md) and regime-matrix decision memo (s4_enhancement/README_REGIME_MATRIX_DECISION.md).

6.1 Priority — Confirmed Next Step

Retrain the model with the repaired, gap-free dataset (the 34-day gap fix is already committed on main, 26 Jun 2026). This is the confirmed real priority for improving future performance — not the regime matrix. Steps:

  1. Use the complete, repaired dataset (no gaps).
  2. Re-evaluate whether the baseline Sharpe (~0.64–0.75 depending on methodology) holds or improves with data fresh through June 2026.
  3. Confirm via validate_dataset.py that no gaps exist before any future training run — a lesson learned from this session.

6.2 Gap 5 — Microstructure Features (In Progress)

Fetcher implemented (OKX), 697 rows / 30 days generated (oi_change_1h, oi_change_8h, oi_zscore_24h, volume_oi_ratio, funding_rate, funding_sign, funding_extreme). Pending: integrate into the day-30 retrain; reconstruct historical dataset with these features back to 2022 via OKX history.

6.3 Gap 6 — Meta-Regime Filter Deployment (Research Complete, Deploy Pending)

Research complete in s4_enhancement/ (meta_regime_filter.py, walk_meta_regime.py, meta_filtered_walk.py, results in integrated_meta_walk_report.csv). Documented improvement: Winrate 64.79%→72.61%, Sharpe 0.6395→0.8534, Max DD -14.42%→-7.40%. Deploy decision pending a 30-day live baseline sample for comparison.

6.4 Gap 7 — Production-Ready Probabilistic Calibration

Model probabilities behave as ranking signals, not real probabilities. Isotonic/Platt recalibration destroys F1. Requires a dynamic-threshold architecture based on EV percentiles rather than literal p_up — pending live data to validate.

6.5 Regime Matrix — Parallel, Non-Blocking Research Line

Parked (not rejected permanently) per the 26 Jun decision memo:

  1. Repeat the 4×4 (or up to 16-cell) regime matrix at daily scale with 10–14 day smoothing.
  2. Apply the anti-data-snooping protocol already defined (minimum sample size per cell, temporal design/validation split, multiple-comparison correction) — critical given the much smaller daily sample.
  3. Specifically validate the BEAR_AND_HIGHVOL hypothesis with the same 5-layer methodology used for BULL_AND_HIGHVOL.
  4. If validated, combine filters (OR logic) and re-run the retroactive test against the 30 real paper-trading days to confirm a two-speed “gearbox” reduces system idle time without destroying signal quality.
  5. Evaluate the speed-vs-stability trade-off — possibly test a shorter confirmation window (5–7 days) trading some stability for faster reaction to real regime changes.

6.6 From the Statistical Due Diligence — Remaining Critical Tasks

Per statistics/README.md final conclusions, before the system can be considered production-grade:

  1. Live shadow deployment (real-time paper trading validation — critical before production capital).
  2. Calibration-aware walk-forward integration.
  3. Dynamic (EV-percentile-based) thresholds.
  4. Funding/perp basis features.
  5. Microstructure signals (liquidation pressure, realized skew, entropy — beyond current OI/funding work).
  6. Order-flow integration.
  7. Live execution validation at scale.

6.7 Advanced Feature Engineering (Future Targets)

Funding rates, perp basis, liquidation pressure, volatility state, realized skew, entropy, order flow, microstructure features (beyond current OI/funding scope).

6.8 Proper Probabilistic Architecture (Future Targets)

Gradient boosting refinements, probabilistic calibration pipeline, meta-labeling, Bayesian forecasting, ensemble ranking systems.

6.9 Frozen Baseline Protection

The original audited profitable version is frozen under tag S4_DEPLOY_AUDITED_V1, with backup archive S4BTC_AUDITED_BASELINE.tar.gz, guaranteeing rollback capability before any enhancement modification.
